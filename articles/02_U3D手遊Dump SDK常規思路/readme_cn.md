# U3D 手游 Dump SDK 的常规思路

[📖 繁體中文](readme.md)　|　[📖 简体中文](readme_cn.md)

这篇把 Unity 手游常见的 SDK Dump 问题分成两条线来看：静态 Dump 与动态 Dump。它不是在堆工具清单，而是整理出两类最常见的阻碍，以及对应能得到的结果。

## 🧩 Dump 思路

| 思路类型 | 主要处理方向 | 适合处理的问题 |
| --- | --- | --- |
| 静态 Dump | 先确认 metadata 与游戏资源结构是否被改动 | 适合处理工具直接报错、无法正常解析的情况 |
| 动态 Dump | 先确认运行期 API 是否仍能被正常取得 | 适合处理 API 被隐藏、工具拿不到有效信息的情况 |

## 📦 静态 Dump

静态路线的重点，是先判断 `global-metadata.dat` 和 `libil2cpp.so` 是否还维持常规结构。这篇整理出来的结论是，很多卡住的原因不在工具本身，而在 metadata 被改动后，常规解析路径已经不再成立。

它的价值在于先把问题分类清楚，让人知道该优先看档案结构，还是先怀疑工具对结构的理解已经过时。

有实际案例，展示 & 解决了其中一种anti静态dump的情况。

## ⚙️ 动态 Dump

动态路线则是看运行期的 API 取得流程。这篇把核心问题收敛成一件事：有些样本不是不能 Dump，而是把 `il2cpp` 相关入口藏起来了，导致工具拿不到该拿的资讯。

这类问题的结果通常不是单纯换工具就能解决，而是要先搞清楚 API 是怎么被转交和隐藏的。文章的重点就在这里，帮你把动态 Dump 的阻碍先分清楚。

有实际案例，从头到尾详细分析了anti 动态 Dump的原理和解决思路

## 🎯 适合谁看

如果你常在 U3D 手游上卡住，但又不确定问题是出在 metadata、API 暴露，还是工具本身，这篇会比较适合先看。

## 💬 一句话说完

这篇把 U3D 手游的 SDK Dump 拆成静态与动态两条主线，重点放在它们各自最常见的阻碍与收敛结果。
