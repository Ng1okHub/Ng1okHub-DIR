# U3D 手遊 Dump SDK 的常規思路

[📖 繁體中文](readme.md)　|　[📖 简体中文](readme_cn.md)

這篇把 Unity 手遊常見的 SDK Dump 問題分成兩條線來看：靜態 Dump 與動態 Dump。它不是在堆工具清單，而是整理出兩類最常見的阻礙，以及對應能得到的結果。

## 🧩 Dump 思路

| 思路類型 | 主要處理方向 | 適合處理的問題 |
| --- | --- | --- |
| 靜態 Dump | 先確認 metadata 與遊戲資源結構是否被改動 | 適合處理工具直接報錯、無法正常解析的情況 |
| 動態 Dump | 先確認運行期 API 是否仍能被正常取得 | 適合處理 API 被隱藏、工具拿不到有效信息的情況 |

## 📦 靜態 Dump

靜態路線的重點，是先判斷 `global-metadata.dat` 和 `libil2cpp.so` 是否還維持常規結構。這篇整理出來的結論是，很多卡住的原因不在工具本身，而在 metadata 被改動後，常規解析路徑已經不再成立。

它的價值在於先把問題分類清楚，讓人知道該優先看檔案結構，還是先懷疑工具對結構的理解已經過時。

有實際案例，展示 & 解決了其中一種anti靜態dump的情況。

## ⚙️ 動態 Dump

動態路線則是看運行期的 API 取得流程。這篇把核心問題收斂成一件事：有些樣本不是不能 Dump，而是把 `il2cpp` 相關入口藏起來了，導致工具拿不到該拿的資訊。

這類問題的結果通常不是單純換工具就能解決，而是要先搞清楚 API 是怎麼被轉交和隱藏的。文章的重點就在這裡，幫你把動態 Dump 的阻礙先分清楚。

有實際案例，從頭到尾詳細分析了anti 動態 Dump的原理和解決思路

## 🎯 適合誰看

如果你常在 U3D 手遊上卡住，但又不確定問題是出在 metadata、API 暴露，還是工具本身，這篇會比較適合先看。

## 💬 一句話說完

這篇把 U3D 手遊的 SDK Dump 拆成靜態與動態兩條主線，重點放在它們各自最常見的阻礙與收斂結果。
