# 🛡️ Appdome分析與繞過：把一個「一碰就死」的樣本，拆到真正能讀懂

[📖 繁體中文](readme.md)　|　[📖 简体中文](readme_cn.md)

做過 App 保護分析的人，大概都遇過這種場景。

App 一啟動就閃退，Frida 一掛上去就跳 `Security Threat Detected`，換個簽名沒用，改個環境也沒用，連真正的業務邏輯都還沒摸到，整個分析流程就先被卡死。

這篇文章，就是從這種幾乎沒辦法下手的狀態開始，一路把 Appdome 的保護鏈拆開。

它不是單純列出幾個檢測點，也不是只給結論不給過程。更重要的是，內容把能確認的部分和還在追的部分分得很清楚，哪些地方已經處理到、哪些地方只是縮小範圍，都有實測支撐。

## ⚡ 它有意思的地方，不只是「過了」

很多文章寫到這類題目，重點通常會停在「能不能繞過」。但這篇更有價值的地方，在於它把原本糾纏在一起的啟動期檢測、Hook 檢測、注入檢測、Root 檢測和簽名校驗，一段段拆成可以驗證的鏈路。

你看到的不只是「怎麼過」，而是每一類現象最後被追到哪裡、處理到什麼程度，以及哪些結果在文中有明確驗證。

## 🧩 這篇文章，實際處理了哪些 Appdome 檢測點？

比起抽象地說「這篇很完整」，更重要的是它到底處理了哪些真正卡人的檢測。下面這張表，只保留原文裡明確做到、或明確寫出驗證結果的部分。

| 檢測類型 | 文章裡處理到的內容 | 文章中的結果 |
| --- | --- | --- |
| 啟動期 / 初始化 | 鎖定核心檢測模組，並先把啟動期的阻礙清掉 | 後續分析得以繼續往下走 |
| 檢測線程主鏈 | 追到主檢測流程 | 一個小操作，就能先 bypass 掉大多數檢測 |
| 核心模組校驗 | 把核心模組本身的校驗點拆出來 | 相關彈窗可先壓住 |
| Frida Hook 檢測（一） | 確認 `Security Threat Detected` 與系統庫校驗有關 | 相關提示可先被處理掉 |
| 注入檢測 | 定位到注入痕跡相關的檢測 | 注入提示可被壓住一段時間 |
| Frida Hook 檢測（二） | 追到 Frida 預設 Hook 特徵 | 這一輪檢測可被繞過 |
| Root / Magisk 檢測 | 定位到 root 與 Magisk 相關路徑 | 主要 root 彈窗可被壓住 |
| 簽名校驗 | 定位到重打包後的簽名檢查 | 簽名檢測不再是阻礙 |
| 功能層延伸 | 從保護層一路走到遊戲功能層 | 後續功能也能繼續分析 |

## 🔍 這篇文章實際做了什麼

它先把保護核心、初始化入口與檢測線程找出來，再把 Hook、注入、Root、簽名幾條鏈分開分析。最後不只停在保護層，還把內容延伸到遊戲功能層，整理出一份完整的分析脈絡。

## 🚧 它解決的是哪種麻煩

最直接的，是把「一進程就死」和各種安全彈窗，拆成幾條可以單獨驗證的問題。讀者拿到的不是一個籠統的 bypass 結果，而是知道幾種常見檢測現象各自從哪裡來的。

## ✨ 讀完之後，你會帶走什麼

你帶走的，不只是某個樣本的結論，而是一個高密度保護樣本怎麼被拆成可追、可驗證、可逐步處理的幾條線。

## 🎯 我會推薦誰看

如果你想系統化理解 Appdome 的保護鏈，或常常被 `Security Threat Detected`、注入檢測、Root / Magisk、重簽名問題卡住，這篇會比較有價值；如果你想看的不只是單一技巧，而是完整樣本怎麼被一步步拆開，這篇也很適合。
